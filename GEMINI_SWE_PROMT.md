# CareerPilot AI — SWE & Tech Lead Collaboration Workflow

Этот файл описывает процесс взаимодействия между Архитектором (Gemini) и Исполнителем (SWE-1.6 в Windsurf).

---

## 1. Анализ архитектуры (Техлид / Gemini)
```
Прочитай эти файлы перед началом работы:
   - GEMINI.md — твоя роль и правила
   - docs/CAREERPILOT_AI_CONTEXT_BACKUP.md — реальный статус проекта (раздел ## Update)
   - ROADMAP.md — план, что сделано и что нет
   - docs/FRONTEND_BACKEND_CONTRACT.md — API контракт
                                                                                                      
   После прочтения скажи кратко: какие слайсы реализованы и какая следующая задача по ROADMAP. Если после задачи или щас нужно делать релиз, описываешь его красивый текст и наименование, тег для github, если нет то пропусти
```
---

## 2. Анализ (Техлид)
```
Задача: [ОПИСАНИЕ ЗАДАЧИ], выбери сам более предпочтительную по приоритету.
                                                                                                      
   Прочитай файлы:
   - backend/src/main/java/... (найди похожий реализованный слайс для понимания паттернов)
   - docs/FRONTEND_BACKEND_CONTRACT.md (секция с нужным endpoint)
   - docs\TASK_PLAN.md (шаблон задачи из GEMINI.md)
                                                                                                      
   Реализуй: только план, не код.
   Создай docs/tasks/TASK_{NAME}.md по шаблону из GEMINI.md.
```

## 3. Запуск SWE-1.6 в Windsurf (Исполнитель)
```
Прочитай и реализуй задачу по плану:


Дополнительный контекст:
@GEMINI.md (ОБЯЗАТЕЛЬНО прочитай раздел "⚠️ Известные ошибки и паттерны (Lessons Learned для SWE-1.6)" перед началом работы!)
@docs/FRONTEND_BACKEND_CONTRACT.md
@docs/CAREERPILOT_AI_CONTEXT_BACKUP.md (прочитай ## Update блоки для понимания текущего состояния)

Следуй порядку реализации из плана.
Не меняй файлы вне scope задачи.
После каждого шага кратко пиши, что сделал.
ОБЯЗАТЕЛЬНО перед завершением выполни локально в frontend npm.cmd run lint и npm.cmd run build, а в backend .\mvnw.cmd clean compile (и тесты), чтобы убедиться в отсутствии ошибок линтинга и сборки!
После реализации выполни проверки из раздела "Проверки".
В конце если были ошибки или нюансы — обнови раздел "⚠️ Известные ошибки и паттерны" в GEMINI.md, но только если ты точно уверен что решение правильное и сооветствует best practics.
```

## 5. Гит коммит и пуш (Исполнитель)
```
   Сделай коммит всех git status изменений и пуш в репозиторий.

   Правила для коммита:
   - Сообщение в прошедшем времени безличной форме (добавлено, обновлено, изменено, исправлено и т.д.)
   - Структурируй по категориям (Backend, Frontend, Документация, Конфигурация и т.д.)
   - Не перечисляй каждый файл, описывай общие изменения по категориям
   - Используй префикс conventional commits: feat:, fix:, refactor:, docs:, chore:, test:
```
