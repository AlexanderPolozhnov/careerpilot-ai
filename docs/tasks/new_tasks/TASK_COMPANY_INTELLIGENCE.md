# Task: Company Intelligence Page (Профиль компании)

## Контекст и цель

Сейчас компании существуют только как справочник, и их можно посмотреть/отредактировать в списке `CompaniesPage`.
Цель — создать отдельную страницу компании (`CompanyDetailPage`), которая будет служить хабом (Intelligence Page) для всей информации, связанной с этой компанией.
На этой странице пользователь должен видеть:
- Данные о компании (индустрия, размер, локация, сайт, описание).
- Все вакансии, сохраненные для этой компании (с их статусами).
- Все отклики (Applications), связанные с этой компанией (Kanban view или List view).
- Заметки и контакты по компании (можно использовать поле `description` или добавить новое).

- `frontend/src/services/application.service.ts` — загружать отклики (потребуется отфильтровать отклики по списку вакансий этой компании).

## Точная реализация (Frontend)

Задача в основном касается композиции уже существующих данных на одной странице.

### 1. Роутинг

В файле конфигурации роутов (например, `App.tsx` или `routes/index.tsx`):
```tsx
<Route path="companies/:id" element={<CompanyDetailPage />} />
```

### 2. Загрузка данных (CompanyDetailPage.tsx)

Страница должна делать параллельные запросы (или использовать `useSuspenseQueries` / несколько `useQuery`):
1. `companyService.get(id)` — для шапки и описания.
2. `vacancyService.list({ companyId: id })` — для списка вакансий.
3. Отклики. У `applicationService` нет фильтра по `companyId`, но можно сделать следующее:
   - Либо просто загрузить все `applicationService.list()` и отфильтровать локально: `apps.filter(a => a.vacancy.company.id === id)`. (Так как пока пагинация не критична).
   - Либо использовать бэкенд (если в `GET /applications` добавить фильтр `companyId`). Для начала достаточно локальной фильтрации всех откликов пользователя, если их не тысячи.

### 3. Верстка страницы

**Шапка (Header):**
- Логотип компании (или заглушка с первыми буквами имени).
- Название, ссылка на веб-сайт (иконка ExternalLink), индустрия, размер.
- Кнопка "Редактировать" (открывает модалку `CompanyForm`).

**Вкладки (Tabs):**
Использовать стейт `activeTab` ('overview', 'vacancies', 'applications').

- **Overview (Обзор):**
  Показывает поле `description` (с поддержкой Markdown, если реализовано).
  Блок "Статистика": всего вакансий (N), активных откликов (M).

- **Vacancies (Вакансии):**
  Рендерит список или сетку компонентов `VacancyCard` (можно переиспользовать верстку из `VacanciesPage`, убрав фильтры).

- **Applications (Отклики):**
  Простой список (List view) откликов на эту компанию с указанием вакансии, статуса (в виде цветного бейджа) и даты обновления.

### 4. Доработка CompaniesPage.tsx

- На странице со списком компаний добавить обработчик клика на строку (или кнопку "Подробнее"), который делает `navigate('/companies/' + company.id)`.

## Риски и что проверить

- **Ограничения API:** Текущий `application.service.ts` и бэкенд могут не отдавать сразу все отклики (пагинация). Если отфильтровать только первую страницу `list()`, можно потерять отклики этой компании. Решение:
  - Идеально: попросить бэкенд разработчика (себя) добавить `companyId` в спецификацию `GET /applications` в `ApplicationServiceImpl.java`.
  - В рамках текущей задачи: добавить в `ApplicationParams` фронтенда `companyId?: string`, а на бэкенде в `ApplicationServiceImpl.java -> getSpec()` добавить проверку:
    ```java
    if (companyId != null) {
        predicates.add(cb.equal(root.get("vacancy").get("company").get("id"), companyId));
    }
    ```
    (Это займет 2 строчки кода в бэкенде и сделает систему надежной).
